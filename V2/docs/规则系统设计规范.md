# 规则系统 v2 设计规范（RuleSpec 2.0）— V2 实施版

> **文档状态**：v1.1（2026-08-04）｜ **适用范围**：模具 BOM 生成工具的规则推理层
> **与初稿差异**：① 按需求移除「同类合并」（无 merge）；② 2026-08-04 新增 **spec 域**（输出规格/型号）——现共 **10 个域**，流水线、示例、词汇表同步修订。
> **独立性**：本系统从零独立构建，不兼容、不迁移旧系统任何规则内容；旧系统仅在 §11 作对照。

---

## 1. 适用范围与目标

### 1.1 适用范围（In Scope）

规则系统只做一件事：**在 BOM 生成流水线中，把"零件实体"决策为"BOM 行属性"**。

| 决策类别 | 说明 |
|---|---|
| 实体过滤 | 哪些 Body 进入 BOM 候选（毛坯、布尔隐藏、油缸附属等） |
| 名称归一化 | 全角→半角、同义词（螺丝→螺钉）、模号截断 |
| GR 分类 | 零件级与规格级 GR 判定（调整板 40\*60\*12 → 仓库备件） |
| 材质 / 热处理 | 按零件名或 GR 决定 |
| 加工备注 | 主备注（覆盖）+ 追加备注（叠加） |
| 配套件 | 按 GR 或零件名补螺钉/垫圈，含免配套控制 |
| 零件编号 | 按 GR 分段编号范围 |
| 测量控制 | 跳过规格测量（非建模件、外购件） |
| 外购数量 | 固定数量（热流道 = 1 件） |

**明确排除**（Out of Scope）：CATIA COM、STP 导出、几何测量算法阈值、BOM 写出格式、GUI 布局。**明确排除：同类合并**——不做任何同类型规则的合并逻辑（合并与否由建模保证，或未来以独立机制扩展）。

### 1.2 设计目标

1. **单一真理源**：一套统一规则模型，无平行表、无引擎内硬编码规则；
2. **全声明式**：规则只描述"何时 → 置何值"；
3. **确定性**：同规则集 + 同输入 → 同输出；
4. **可审计**：每个输出属性携带来源（规则 id + 版本）；
5. **先验证后生效**：任何写入必须过门禁；
6. **可测试**：基准语料是一等公民，规则与测试一一关联。

### 1.3 术语表

| 术语 | 定义 |
|---|---|
| 实体 | 规则作用对象：group → part → spec → companion |
| 属性 | 实体上可被写入的字段，有固定词汇表，每属性**唯一归属域** |
| 规则 | 声明式语句：`when（全满足）→ then（写属性）` |
| 规则域 | 业务类别，共 10 个（§4.1） |
| 优先级 | 规则强度，数值越大越优先（§5.1） |
| 特异性 | 条件具体程度的可计算度量（§5.2） |
| 基准语料 | 人工确认的"输入→期望输出"样本集 |
| 候选建议 | 引擎从历史 BOM 生成的提案，**永不自动生效** |

## 2. 总体架构

### 2.1 分层

```
L3 规则集层   rules/manifest.json（版本）+ rules/<域>.rules.json
L2 引擎层     流水线调度 → 匹配 → 裁决 → 写入（带 provenance）
L1 实体层     group → part → spec → companion
L0 数据源     CATPart 解析结果 / 几何测量结果
```

### 2.2 流水线（10 域，无 merge）

```
实体(Body) → [filter] → [normalize] → [gr] → [measure 闸门] → [material]
           → [remark] → [companion] → [purchase] → [number] → BOM 行
```

- 每方括号 = 一个规则域阶段；域内按「priority → specificity → id」排序，first-wins；
- `gr` 域中 `scope=spec` 的规则仅在规格已知时参与（测量后精化），其余规则一次裁决；
- `measure.skipMeasurement=true` 的实体跳过测量，规格未知时规格级规则自动不参与；
- `purchase` 与 `number` 在行级执行。

## 3. 统一规则模型

### 3.1 规则 Schema（唯一模型，所有域共用）

```json
{
  "id":       "gr.adjust-plate.spec.001",
  "domain":   "gr",
  "priority": 700,
  "scope":    "spec",
  "when": {
    "part.workingName": {"op": "eq", "value": "调整板"},
    "spec.value":       {"op": "eq", "value": "40*60*12"}
  },
  "then": { "gr": "仓库备件" },
  "meta": {
    "status": "active", "version": 1,
    "author": "littledark", "createdAt": "2026-08-04", "updatedAt": "2026-08-04",
    "rationale": "12 厚调整板走仓库", "tests": ["corpus.gr.adjust-plate.001"]
  }
}
```

**字段契约（全部必填）**

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | string | §7.1 命名规范，全局唯一 |
| `domain` | enum | 10 个固定域之一 |
| `priority` | int | 0–1000，默认 500；越大越优先 |
| `scope` | enum | global / group / part / spec / companion |
| `when` | object | 条件映射，隐式 AND；空 when 仅限 global |
| `then` | object | 只写本域授权属性；null = 强制置空 |
| `meta.status` | enum | draft / active / deprecated / retired |
| `meta.version` | int | ≥1，每次修改 +1 |
| `meta.tests` | array | 关联语料 id，必须存在 |

### 3.2 条件语法（when）

字段见属性词汇表（§4.2）。全部条目 AND；缺字段不命中。

| op | 语义 | 形参 |
|---|---|---|
| `eq` | 全等 | `value` |
| `contains` | 包含子串 | `value` |
| `keyword` | 命名规则关键词：零件名按分割符（空格/逗号/斜杠/竖线/顿号，含全角）分词后，`value`（或列表=任一）须等于某个**完整词**才命中——『油缸』不误命中『开模油缸』；完全命中=命名规则命中 | `value` / `value[]` |
| `prefix` / `suffix` | 前缀 / 后缀 | `value` |
| `regex` | 正则（search 语义，可用 ^$ 锚定） | `value` |
| `in` | 属于列表 | `value[]` |
| `range` | 数值区间（含边界） | `min`, `max` |
| `exists` | 字段存在性 | `true/false` |

所有匹配器可 `"negate": true` 取反。**匹配语义完全显式**：不做任何隐式特判（旧系统斜杠 AND 拆分等不继承）。

### 3.3 动作语法（then）

| 值类型 | 写法 | 示例 |
|---|---|---|
| 字面量 | 字符串/数字/布尔 | `"gr": "仓库备件"` |
| 置空 | `null` | `"material": null` |
| 追加 | `{"add": [...]}` | `"remarkAppend": {"add": ["油路按造型加工"]}` |
| 结构化 | 对象/数组 | `"companions": [{"name":"螺钉","spec":"CB16-100","qty":4}]` |

## 4. 分类体系

### 4.1 规则域一览（10 域，无 merge）

| 域 | 用途 | 授权属性（then 可写） |
|---|---|---|
| `filter` | 实体过滤 | `input.skipBody`, `input.skipReason` |
| `normalize` | 名称归一化 | `part.workingName`, `part.aliases` |
| `gr` | GR 分类 | `gr` |
| `spec` | 输出规格（BOM 打印用） | `outputSpec` |
| `material` | 材质/热处理 | `material`, `heatTreatment` |
| `remark` | 加工备注 | `remark`, `remarkAppend` |
| `companion` | 配套件 | `companions`, `suppressCompanions`, `companionGrPolicy` |
| `number` | 零件编号 | `numberRange`, `numberPrefix` |
| `measure` | 测量控制 | `skipMeasurement`, `skipReason` |
| `purchase` | 外购数量 | `purchaseFixedQty` |

> **spec 域（2026-08-04 新增）**：解决"测量规格 ≠ 打印规格"——引擎按测量规格（如 `100*80*50`）匹配，
> 命中则 BOM 规格列打印 `outputSpec`（如 `BZ500.80/50`）；无命中时默认打印测量值。
> 典型场景：油缸定位块等型号件。匹配与显示分离，不影响 gr/material/remark 等下游推理。

### 4.2 属性词汇表（when 可用字段，固定）

`part.name` / `part.workingName` / `part.material` / `part.group` / `spec.value` / `spec.count` / `spec.hasMeasured` / `gr` / `quantity` / `input.skipBody` / `input.skipReason`

**唯一归属原则**：每个输出属性有且仅有一个域可写（`OWNERSHIP` 表）。旧系统中"材质"被多个来源写的结构性缺陷，在本系统不可能存在。

### 4.3 层级关系

```
规则集 → 域 ×10（每域一文件）→ 规则（统一 schema）→ when 条件 / then 动作
实体：group → part → spec → companion
```

## 5. 优先级与裁决算法

### 5.1 优先级

0–1000，默认 500，越大越优先。建议分带：800-1000 显式例外/覆盖；500-799 常规业务；300-499 通用/兜底/追加；0-299 保留。

### 5.2 特异性

特异性 = 已命中条件字段权重之和：`spec.*`=40，`gr`=30，`part.name/workingName`=25，`part.material`=20，`part.group`=15，`quantity`=10，其他=5。

### 5.3 裁决算法（每属性 first-wins）

```
候选 = { r ∈ 域.active | r.when 全命中，且属性 ∈ r.then }
排序 = priority 降序 → specificity 降序 → id 升序
top = 候选[0]；候选空 → 不写入
top.then[属性] == null → 强制置空
否则 属性 = top.then[属性]，provenance[属性] = (top.id, top.version)
若 top 与 次名 同 (priority, specificity) 且值不同 → RuleConflictError（零猜测）
```

追加属性（`remarkAppend`、`companions`）取全部有效候选并集，按优先级升序拼接。

## 6. 冲突处理与裁决原则

| 类型 | 定义 | 处理 |
|---|---|---|
| C1 同值竞争 | 同强度同值 | 允许，取 id 小者 |
| C2 异值竞争 | 同强度异值 | **阻断错误**（静态判 / 干跑判 / 运行期判） |
| C3 强弱竞争 | 强度不同 | 强者胜（正常裁决） |
| C4 跨域矛盾 | 不同域产物矛盾（qty 固定但仍有配套） | 静态（同规则内互斥键）+ 运行期检测 |
| C5 层级冲突 | part vs spec 规则同属性 | 规格级因特异性天然胜出 |

**裁决原则**：① 唯一归属 ② 显式优先 ③ 具体优先 ④ 规格高于零件 ⑤ 零猜测 ⑥ 全可审计。

**C4 静态清单**：`purchaseFixedQty` 与 `companions` 同规则互斥；`suppressCompanions` 与 `companions` 同规则互斥。

## 7. 命名规范与编写风格

### 7.1 规则 id 规范

```
<domain>.<category>.<scope>.<seq>
domain ∈ 10 域；category = 小写 kebab-case ASCII ≤24 字符；scope ∈ 5 作用域；seq = 3 位数字
示例：gr.adjust-plate.spec.001 / material.mold-frame.part.001 / companion.thermal-runner.part.001
```

### 7.2 文件组织

```
rules/
├── manifest.json            # 版本（semver）、作者、域列表
├── <domain>.rules.json ×10  # 每域一文件
└── snapshots/               # 每次通过门禁的写入快照 <版本>.json
corpus/<域>.json             # 基准语料
candidates/                  # 学习候选（永不自动生效）
```

### 7.3 编写风格约定

JSON 2 空格缩进、双引号、UTF-8；字段顺序 `id → domain → priority → scope → when → then → meta`；条件字段顺序 `part.* → spec.* → gr → quantity`；规则体不写注释，意图写 `meta.rationale`；兜底规则 rationale 以「兜底：」开头且 priority ≤ 400。

## 9. 生命周期管理

### 9.1 状态机

```
draft ──(门禁全过)──→ active ──(标记)──→ deprecated ──(存档)──→ retired
  ↑                     │
  └──────(退回/修改)────┘
retired ──(仅大版本升级时物理清除)──→ 删除
```

### 9.2 版本与快照

- 规则级 `meta.version` 每次修改 +1；
- 规则集 semver：MAJOR=可物理删 retired / MINOR=增改规则 / PATCH=仅 meta 修订；
- 每次写入通过门禁 → `snapshots/<版本>.json` 全量快照 + 原子写回；未显式给版本时自动读 manifest 文件版本 bump PATCH+1；
- 回滚：`restore <版本>` → 恢复快照 + 版本 bump PATCH+1 防同名冲突。

### 9.3 增 / 改 / 删

| 操作 | 流程 |
|---|---|
| 新增 | 生成 id（§7.1）→ 填规则 → 门禁全过转 active；失败停留 draft 并输出报告 |
| 修改 | 保留 id，version+1，updatedAt 更新，重跑门禁 |
| 删除（软） | status: active → deprecated（保留在文件） |
| 删除（硬） | 仅 MAJOR 升级时物理清除 retired |

### 9.4 验证门禁（G1-G6）

| 门禁 | 内容 | 失败处理 |
|---|---|---|
| G1 结构 | JSON Schema 全量校验 | 阻断，字段级错误 |
| G2 命名 | id 唯一/格式、name 域内唯一 | 阻断 |
| G3 引用 | when 字段 ∈ 词汇表；then ∈ 域授权表；tests 指向存在的语料 | 阻断 |
| G4 冲突 | 静态 C2（when 全同 + 异值）+ C4 清单 | 阻断，输出规则对 |
| G5 行为 | 全量语料干跑：受影响属性 100% 一致、0 回归 | 阻断，输出差异报告 |
| G6 快照 | 写 snapshot + 原子替换 | — |

失败 ≠ 丢弃：规则以 draft 保留，报告指引修正方向。

语料样本格式：

## 11. 与旧系统的主要差异

| 维度 | 旧系统（gr_rules.json，16 键） | 新系统（RuleSpec 2.0，10 域） |
|---|---|---|
| 结构 | 16 个异构顶层键 | 1 套统一规则模型 + 10 域 |
| 优先级 | 隐式（decision_order 列表位置 + 引擎硬编码） | 显式 priority + 特异性公式 + 确定性裁决 |
| 冲突 | 静默覆盖或不处理 | 显式报错（C2 阻断），零猜测 |
| 平行表 | 三套平行表（已删）+ learned 完整形态补救 | 属性唯一归属域，结构层不可能存在 |
| 规格级 | 仅 GR 支持规格级覆盖 | 任何域支持 spec 作用域 |
| 学习 | 直写 learned_mapping（污染权威数据） | 只产出 candidates，人工确认才成规则 |
| 删除 | 全量重建写入才可删 | 软删除状态机 + 快照回滚 |
| 测试 | 外部脚本，与规则无绑定 | corpus 一等公民 + tests 绑定 + 门禁强制干跑 |
| 同类合并 | merge_rules 键 | **已移除（需求 1）**，无任何合并逻辑 |
| 匹配语义 | 斜杠 AND 拆分等隐式特判 | 全部显式算子，无隐式语义 |

## 12. 设计理念

单一真理源 / 显式优于隐式 / 声明式非命令式 / 可审计优先 / 先验证后生效 / 学习与权威分离 / 确定性即信任。
