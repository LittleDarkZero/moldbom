# V2 规则编辑器使用说明（RuleSpec 2.0）

> 运行：`python editor.py` ｜ 规则集：`V2/rules/` ｜ 快捷键：Ctrl+Z 撤销 / Ctrl+Y 重做
> 目标场景：为每个零件录入三类信息——**规格（尺寸/材质/公差）、加工说明、GR名**。

---

## 1. 界面布局

```
┌────────────────────────────────────────────────────────────────┐
│ 工具栏：保存（门禁+快照）｜验证（语料干跑）｜撤销｜重做｜＋新建规则     │
├──────────────┬─────────────────────────────────────────────────┤
│ 左侧规则树    │ 右侧详情面板（选中规则后显示）                       │
│ 📁 gr（5）    │ ┌ 错误面板：实时校验未通过项（红色）              ┐  │
│   · 规则条目  │ ├ 基本信息：id(只读)/名称/作用域/优先级/状态/删除  │  │
│ 📁 material  │ ├ 条件 when：字段/算子/值/取反（AND）＋添加条件    │  │
│ 📁 remark    │ ├ 动作 then：属性/值（类型化输入）＋添加动作        │  │
│ …共 9 个域    │ └ 元信息：版本/作者/理由/测试引用/语料速查        │  │
├──────────────┴─────────────────────────────────────────────────┤
│ 底部状态栏：操作反馈 + 即时校验结果                                 │
└────────────────────────────────────────────────────────────────┘
```

- **左侧树**：9 个规则域分组（filter/normalize/gr/material/remark/companion/number/measure/purchase），域内按**优先级降序**排列；颜色标识状态（active 白 / draft 黄 / deprecated 灰）；**拖拽条目 = 交换优先级**（裁决顺序）；点击选中。
- **右侧详情**：四张分组卡片，编辑即实时校验，错误内联显示在顶部红色面板。
- **保存**：强制过门禁 G1-G6（结构/命名/引用/冲突/语料干跑/快照），通过才写回并自动快照；失败给内联报告，不改坏线上数据。

## 2. 核心概念：三类信息落在哪里（重要）

V2 遵循"每个属性唯一归属域"：一条规则只能写**本域**的属性。因此"一个零件的完整档案"由**最多 3 条规则**组成（gr / material / remark），它们通过相同的条件（when）绑定到同一零件：

| 您想录入的信息 | 在 V2 中的位置 | 示例 |
|---|---|---|
| 零件名 / 规格尺寸 | **条件** `when` 里的 `part.workingName` / `spec.value`（用于定位零件、区分规格） | 调整板、40*60*12 |
| 材质、热处理 | material 域规则的**动作** `then.material` / `then.heatTreatment` | 45# |
| 加工说明（工艺/方式/注意事项） | remark 域规则的**动作** `then.remark`（主备注，**多行**）/ `then.remarkAppend`（追加） | 外协精加工到位 |
| GR名 | gr 域规则的**动作** `then.gr` | 仓库备件 |
| 公差 | **暂无专用属性**——可写入加工说明文本；如需独立字段后续扩展 | — |

> 规格尺寸本身由测量引擎得到（`spec.value` 是**输入**，× 号自动归一化为 \*）。您录入的是"**这条规格下该怎么决策**"——例如"调整板 且 40\*60\*12 → 仓库备件"。

## 3. 单个零件录入：逐步操作

### 第 1 步：定位零件（两种方式）

- **已有规则**：左侧树展开对应域（如 gr）→ 点击该零件的规则条目 → 右侧出现详情；
- **还没有规则**：工具栏「＋新建规则」→ 内联表单（**默认值已预填**）：
  - 域：选 gr / material / remark（按要录入的信息选）；
  - 类别：零件族英文名（如 `adjust-plate`），只允许小写字母/数字/短横线；
  - 作用域：part（规格级差异选 spec，配合 spec.value 条件）；
  - 优先级：默认 500（规格级例外建议 700）；
  - 名称：可填中文名便于识别 → 点「创建规则」。
  - 创建后自动生成 id（如 `gr.adjust-plate.part.001`）、作者/日期、首条件行 + 首动作行，状态 draft。

### 第 2 步：填「条件 when」——告诉引擎"这条规则管哪个零件"

1. 条件行：字段选 `part.workingName` → 算子 `eq`（精确）或 `contains`（包含）→ 值填零件名；
2. 要区分规格：点「＋添加条件」加一行 → 字段 `spec.value` → 算子 `eq` → 值填规格（如 `40*60*12`，输 `40×60×12` 也会自动归一化匹配）；
3. 高级：`regex`（正则，search 语义可用 ^$ 锚定）、`range`（区间）、`in`（列表）、勾选「取反」；
4. 条件全部满足才命中（AND）。

### 第 3 步：填「动作 then」——写入信息

- **gr 域规则**：动作属性 `gr` → 值填 GR名（如 仓库备件）；
- **material 域规则**：`material` → 材质；`heatTreatment` → 热处理（可直接留空或置空）；
- **remark 域规则**：`remark` → **多行文本框**，回车换行，失焦即保存（如：外协精加工到位 / 按造型刻字 两行）；追加内容用 `remarkAppend`（每行一项，可与主备注叠加）；
- 每行右侧「×」删除动作；「置空」勾选 = 强制清空该属性（覆盖低优先级规则）。

### 第 4 步：元信息与状态

- 理由（rationale）：写明这条规则的意图（必填习惯，便于日后维护）；
- 测试（tests）：可选关联语料 id（输入后回车添加，点击 chip 移除）；
- **状态**：新建默认 `draft`（不参与推理）——录入完成后改为 `active` 才生效；弃用改 `deprecated`（软删除）。

### 第 5 步：保存

- 点「保存」→ 门禁全过 → 状态栏显示"已保存并快照 vX.Y.Z"（快照在 `rules/snapshots/`，可回滚）；
- 被拦截时：右侧显示内联报告（结构错误/干跑差异），修正后重存；`Ctrl+Z` 可撤销任意步骤。

## 4. 批量录入与模板

| 方式 | 做法 | 适用 |
|---|---|---|
| **连续新建** | 重复「＋新建规则」，id 自动递增序号（同一类别/域/作用域下） | 少量零件逐条录入 |
| **家族式配置** | material/remark 规则用 **gr 条件**而非零件名条件（如 `when gr = 模架` → 材质 50#锻件），一条规则覆盖整个 GR 家族 | 同 GR 批量定材质/备注 |
| **JSON 模板** | 直接编辑 `rules/<域>.rules.json`：复制一条已有规则 → 改 id/条件/值 → 编辑器打开即校验，保存时全量门禁 | 大量相似规则（复制粘贴最快） |
| **CLI 骨架** | `python -m rulespec new gr --category adjust-plate --scope part --priority 500` 生成模板骨架 | 脚本化批量准备 |
| **语料回归** | `corpus/` 里加样本（given/expect），点「验证」全量干跑 | 录入后防回归 |

## 5. 完整示例：为「调整板 40*60*12」录入 GR、材质、加工说明

**目标**：调整板，规格 40\*60\*12 → GR=仓库备件、材质=45#、加工说明=外协精加工到位 + 去毛刺。

### 5.1 GR 名（gr 域）

1. 左侧树展开 `gr` → 已存在 `gr.adjust-plate.spec.001`（示例规则），点击选中；
   - 若无：工具栏「＋新建规则」→ 域 `gr`、类别 `adjust-plate`、作用域 `spec`、优先级 `700` → 创建。
2. 「条件 when」卡片确认两行：`part.workingName eq 调整板`、`spec.value eq 40*60*12`（少一行就「＋添加条件」补）；
3. 「动作 then」卡片：`gr = 仓库备件`；
4. 「元信息」：状态改为 `active`，理由填"12 厚调整板为仓库标准件"。

### 5.2 材质（material 域）

5. 「＋新建规则」→ 域 `material`、类别 `adjust-plate`、作用域 `spec`、优先级 500 → 创建；
6. 条件补两行：`part.workingName eq 调整板`、`spec.value eq 40*60*12`；
7. 动作：`material = 45#`（`heatTreatment` 留空或删除该动作行）；
8. 状态 → `active`。

### 5.3 加工说明（remark 域）

9. 「＋新建规则」→ 域 `remark`、类别 `adjust-plate`、作用域 `spec` → 创建；
10. 条件同上两行；
11. 动作：`remark` 多行文本框输入：
    ```
    外协精加工到位
    去毛刺
    ```
    （失焦自动保存，回车换行）
12. 状态 → `active`。

### 5.4 保存生效

13. 点「保存」→ 状态栏：已保存并快照（如 v1.0.1）；
14. 可选：点「验证」看全量语料干跑是否全绿；
15. 验证效果：新建一条临时规则时也可在推理 API 里直接确认——
    `RuleEngine(rules).infer("调整板", spec_value="40*60*12")` → gr=仓库备件、material=45#、remark=外协精加工到位\n去毛刺。

**如果规则没生效，按此排查**：① 状态是否 active（draft 不参与）② 条件是否被更优规则抢先（优先级/特异性，可在树中拖拽调序）③ 条件值是否匹配（零件名/规格写法）④ 是否保存成功（门禁报告）。

## 6. 常见问题

| 问题 | 解答 |
|---|---|
| 新建的规则为什么不生效？ | 默认状态是 draft，改为 active 并保存 |
| 两个规则同时命中谁赢？ | 优先级大者赢；同优先级比特异性（spec 条件 > 零件名）；仍相同则报冲突错误（零猜测） |
| 想删一条规则？ | 状态改 `deprecated` 软删除（保留可追溯）；「删除」按钮为硬删除（两步确认，可 Ctrl+Z 恢复） |
| 改错了？ | Ctrl+Z 撤销（含拖拽/新建/增删行），上限 100 步 |
| 保存被拦？ | 右侧内联报告指出错误（缺字段/引用不存在/干跑差异），修正后重存；数据不会被写坏 |
| 规格写法 | 编辑器里输 `40×60×12` 与 `40*60*12` 等价（自动归一化） |
| 批量同类零件 | material/remark 用 gr 条件做家族级配置，一条管一族 |
